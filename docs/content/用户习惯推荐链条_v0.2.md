# 冰箱侦探 · 用户习惯推荐链条 v0.2

本文档说明 `正式菜品库_200道_v0.2.json` 如何和用户偏好、冰箱食材、厨具条件连接，用于后续 Top 8 推荐算法。

## 1. 输入

用户侧输入：

- `dietaryRules`
- `avoidIngredientKeys`
- `cuisinePreferences`
- `maxCookTime`
- `cookingSkill`
- `kitchenEquipment`
- `pantryItems`
- `fridgeIngredientKeys`

菜品侧字段：

- `minimum_required_ingredients`
- `optional_ingredients`
- `pantry_assumptions`
- `required_equipment`
- `dietary_rules_supported`
- `substitutions`
- `preference_match`

## 2. 推荐顺序

推荐算法建议采用“先硬过滤，再排序打分”。

### 2.1 硬过滤

一道菜如果命中以下任一条件，应从可推荐候选中排除：

1. 用户的 `dietaryRules` 与菜品 `preference_match.dietary_rule_keys` 不兼容。
2. 用户的 `avoidIngredientKeys` 命中 `preference_match.avoid_ingredient_hard_filter_keys`。
3. 用户没有菜品必需厨具，即 `preference_match.required_equipment_keys` 中的必需厨具无法满足。
4. 用户 `maxCookTime` 小于菜品 `cook_time_minutes`。
5. 用户 `cookingSkill` 不在菜品 `preference_match.cooking_skill_fit` 中。

说明：

- `avoid_ingredient_hard_filter_keys` 包含最低必需食材和关键调料。
- `avoid_ingredient_soft_conflict_keys` 只包含可选食材，命中后不必排除，可降低排序或隐藏该可选项。
- 传统菜系如 `sichuan`、`cantonese`、`shandong`、`huaiyang` 会同时命中 `chinese_home`。

### 2.2 食材覆盖度

硬过滤后，对剩余菜品计算冰箱食材匹配：

```txt
核心食材覆盖 = fridgeIngredientKeys 覆盖 fridge_core_match_keys 的比例
替代覆盖 = fridgeIngredientKeys 覆盖 substitution_match_keys 的情况
可选加分 = fridgeIngredientKeys 覆盖 fridge_optional_boost_keys 的数量
调料覆盖 = pantryItems 覆盖 pantry_match_keys 的比例
```

推荐页可以优先展示：

- 核心食材全覆盖的菜。
- 核心食材缺 1 个但有替代食材的菜。
- 核心食材接近全覆盖且用户偏好高度匹配的菜。

### 2.3 用户习惯排序

排序建议权重方向：

```txt
核心食材覆盖度 > 饮食限制兼容 > 忌口无冲突 > 厨具满足 > 时间匹配 > 熟练度匹配 > 菜系偏好 > 可选食材/调料加分
```

简化打分示例：

```txt
score =
  exactCoreIngredientCoverage * 50
  + substitutionCoverage * 12
  + pantryCoverage * 10
  + cuisinePreferenceMatch * 10
  + directCuisinePreferenceMatch * 4-12
  + traditionalCuisineSpecificBoost * 8
  + timeFit * 10
  + skillFit * 8
  + optionalIngredientBoost * 7
  + fullExactCoreBonus * 10
  - missingCorePenalty
```

说明：

- 精确核心食材命中必须高于替代命中，避免“有鸡蛋却优先推荐豆腐替代菜”。
- `fridgeIngredientKeys` 与 `pantryItems` 应合并成可用食材池，用于判断最低必需项，例如豆瓣酱、咖喱块、意面酱这类 pantry 也可能是某道菜的核心必需。
- 具体传统菜系命中应高于泛泛 `chinese_home`，例如用户选择 `sichuan` 时，川菜应获得额外加权。
- 忌口可以有少量扩展规则，例如用户不吃 `mushroom` 时，也应过滤 `canned_mushroom`。

## 3. 输出

推荐结果最多展示 8 道：

- `recipe_key`
- `zh_name`
- `cook_time_minutes`
- `difficulty`
- 已有核心食材
- 缺少核心食材
- 可替代食材
- 缺少调料
- 推荐理由

推荐理由应直接来自匹配链条，例如：

- “你已有番茄、鸡蛋和基础调料，15 分钟内能完成。”
- “你偏好川菜，这道菜命中 `sichuan`，但需要豆瓣酱。”
- “你不吃香菜，香菜只是可选点缀，已为你隐藏。”
- “你没有烤箱，这道菜只需要炉灶和平底锅。”
