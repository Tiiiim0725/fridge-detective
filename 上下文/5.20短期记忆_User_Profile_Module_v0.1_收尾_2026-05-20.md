## 7. Claude Code 执行边界新规则

本窗口发现 Claude Code 容易扩大任务范围，例如：

- 不按步骤等用户确认

尤其核心文件如 services、types、migrations、package、env、layout 等，必须严格限制。

之后页面显示真实错误：

```txt
permission denied for table profiles [code: 42501]
```

### 8.5 42501 权限问题

结论：

- 不是 Anonymous Auth 问题
- 不是 RLS policy 条件问题
- 是 PostgreSQL 表级 GRANT 缺失

RLS policy 只是“允许条件”，但角色还需要表级权限。anonymous user 属于 authenticated role，但 authenticated role 当时没有 profiles 表 SELECT 权限，所以查询被拒绝。

### 8.6 新增 GRANT migration

正确做法不是修改已推送的 001 migration，而是新增：

```txt
supabase/migrations/002_grant_user_profile_permissions.sql
```

核心 SQL：

```sql
grant usage on schema public to authenticated;

grant select, insert, update, delete
on table public.profiles
to authenticated;

grant select, insert, update, delete
on table public.user_preferences
to authenticated;

grant select, insert, update, delete
on table public.kitchen_equipment
to authenticated;

grant select, insert, update, delete
on table public.pantry_items
to authenticated;
```

推送后再次运行 dev 页面，成功。

### 12.2 Data API / GRANT 变化

这是重要长期规则。

Supabase 通知说明新 public 表不会再自动暴露给 Data API。App 使用 supabase-js / PostgREST / GraphQL 访问 public 表时，必须显式 GRANT。

本项目刚刚遇到的：

```txt
permission denied for table profiles [code: 42501]
```

就是该类问题。

长期规则：

以后所有新建 public 表的 migration 必须包含：

1. create table
2. grant
3. enable row level security
4. create policy
5. indexes / constraints
6. trigger

公共只读表例子：

```sql
grant select
on table public.recipes
to anon, authenticated;
```

用户私有表例子：

```sql
grant select, insert, update, delete
on table public.some_user_table
to authenticated;
```

并配合 RLS：

```sql
using ((select auth.uid()) = user_id)
with check ((select auth.uid()) = user_id)
```

### 13.4 六（8）RLS 与安全规则：必须加入 GRANT

````md
#### GRANT 与 Data API 权限规则

由于 Supabase Data API 对 public schema 新表不再默认暴露，所有需要通过 supabase-js / PostgREST / GraphQL 访问的 public 表，migration 必须显式写 GRANT。

用户私有表通常需要：

```sql
grant select, insert, update, delete
on table public.some_user_table
to authenticated;
```
````

公共只读表如 recipes 可考虑：

```sql
grant select
on table public.recipes
to anon, authenticated;
```

GRANT 只提供表级访问能力，RLS policy 仍负责行级限制。两者缺一不可。缺少 GRANT 时可能出现 `permission denied for table ... [code: 42501]`。

````

这个是必须永久进入项目文档的重大策略。
````
